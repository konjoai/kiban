# KT-13.P4 -- Does the generation-fixture harness discover, classify, and report correctly, offline?

**Verdict: PASS**, scoped correctly: this confirms the *mechanism* works, not that it
constitutes the KT-13.1 empirical study (it explicitly does not -- see
`.konjo/killtests/P13/KT-13.1.md`).

## Command

```
python3 -m pytest tests/test_genfixtures.py -v
python3 bin/konjo-eval gen
```

## Fixture set

Three illustrative generation fixtures under `evals/gen_fixtures/`, each modeled on a
real defect class from `konjoai/lopi`'s own `.claude/rules/security.md` (per-fixture
`task.json.source` names the real precedent) but hand-authored rather than produced by a
live `konjo-headless` run -- KT-13.1 found the full live-generation protocol infeasible at
the specified rigor this session:

- `01_webhook_signature_baseline` -- a clean, mitigated candidate diff (HMAC verification
  present before dispatch). **Must classify to zero** on every mechanically-checked class.
- `02_subprocess_no_env_allowlist` -- a candidate diff that spawns `Command::new("sh")`
  over a repo-supplied string with no mitigation. **Must trip**
  `untrusted_input_reaching_exec` (via `lib.threat`'s diff heuristic).
- `03_hardcoded_token` -- a candidate diff with a literal `ghp_...` token in source.
  **Must trip** `secret_in_source` (via `lib.redact.scan_diff`, exact reuse, no new
  pattern).

`tests/test_genfixtures.py` (8 cases) checks discovery, task loading, per-fixture
classification (all three fixtures above), the None-vs-empty-list distinction for
classes this harness does not mechanically check, corpus-level totals, and the
empty-corpus-dir case (0 fixtures, all-zero totals, never an error).

## What actually separates them

Three of the eight taxonomy classes (`secret_in_source`, `unconfigured_permit_branch`,
`untrusted_input_reaching_exec`) are classified by directly reusing an existing kiban
detector against the candidate diff (`lib.redact`, `lib.polarity`, `lib.threat`) -- no new
pattern library. The other five (`unbounded_queue`, `missing_timeout`,
`raw_index_external_input`, `untyped_error_boundary`, `missing_test_failure_path`) have
no kiban detector today and are reported `None` (unclassified), never silently coerced
to zero -- a `None` and a `0` mean different things (not checked vs. checked-and-clean),
and `test_classify_diff_names_unclassified_classes` specifically guards against that
conflation.

## Rescope decision

Ships report-only: `konjo-eval gen` always exits 0 regardless of counts, and the CI
wiring (`.github/workflows/ci.yml`, kiban's own -- not `templates/repo-ci.yml`, since the
fixture corpus is kiban's own generation-quality tracking, not a per-PR concern for a
consuming repo's diff) adds `continue-on-error: true` and `|| true` as belt-and-suspenders
on top of the command's own never-fails contract. Matches Phase 4's own instruction: "This
never blocks... a noisy blocking gate gets disabled within a month."

## Limit carried forward

The seed corpus is illustrative (3 fixtures, hand-authored candidate diffs), not the
KT-13.1 empirical corpus (12-20 tasks, 3 live runs each, drawn from real closed work).
Running the real corpus needs the live-generation half of this harness
(`run_generation`, described but not built this session -- see
`.konjo/killtests/P13/KT-13.1.md`'s "What a real KT-13.1 run requires next"), which
needs a real `konjo-headless`-driven implementation loop this session did not build or
run, on the same reasoning KT-13.1 gives for not rushing it.
